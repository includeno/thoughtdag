# ThoughtDAG 对照 TheBrain 的功能差距清单

> 审计日期：2026-08-27  
> 目的：识别 ThoughtDAG 当前尚未提供、或只提供了部分底层能力的知识图谱工作流。本文不是产品复制计划，也不代表所有差距都应该实现。

## 1. 范围与证据

本次判断使用三类证据：

1. 用户提供的两个 TheBrain 节点菜单截图；
2. TheBrain 官方帮助和官方版本 15 功能页；
3. ThoughtDAG 当前代码、`docs/features_ZH.md`、节点右键菜单、搜索、数据结构和画布操作。

“缺失”表示当前代码中没有对应的数据模型和完整用户工作流；“部分具备”表示已有相近原语，但还不能完成对照产品中的完整任务。只凭截图无法证明的能力，会以官方资料补充；仍无法确认的内容不作为确定结论。

## 2. 先排除：ThoughtDAG 已经有的近似能力

以下项目不能简单写成“没有”：

| 能力 | ThoughtDAG 当前情况 | 与对照工作流的差别 |
| --- | --- | --- |
| 画布全文搜索 | 已有 `Cmd+F`，搜索问题、回答、便签、高光、链接标题和材料名，并定位节点 | 没有结构化条件、查询语法、保存报告和排序分组 |
| 有向父子结构 | 实线 DAG 表达上游→下游的上下文流 | 关系首先是执行语义，不是独立的知识分类父子关系；没有显式“创建父级/子级”菜单 |
| 非层级关联 | 虚线引用边和随动评审边可以连接任意节点 | 没有通用的“跳转关系”对象和用户自定义关系类型 |
| 节点定位和居中 | 搜索、时间线、方向键导航会把节点移到视口中心 | 没有持续的“活动节点邻域模式”，不会只显示父级、子级、兄弟和跳转节点 |
| 内容与附件 | 便签、文件节点、链接快照、PDF 阅读器和节点附件均已存在 | 缺少统一的节点内容工作台、文件夹映射、收件箱和云端按需附件 |
| 多选 | 框选、多节点综合、复制、归档、对齐、导出和删除均已存在 | 不能批量设置标签、类型、图标、颜色和其他元数据 |
| 复制、归档、删除 | 节点右键菜单已支持 | 没有“遗忘后可找回”的独立回收/孤儿治理工作流 |
| 时间线 | 已有节点时间戳、语义事件日志和时间线入口 | 不是日历、提醒、事件管理或持久化事务回放系统 |
| 分享 | 可分享整张只读画布 | 不能给单个节点生成稳定页面和永久链接 |
| 本地自动化 | 已有受权限控制的本地 CLI，能操作项目、节点、连线和材料 | 尚无面向普通用户的图内自动化编辑器、稳定事件订阅和可视化脚本管理 |

## 3. 确认缺失或只部分具备的功能

优先级含义：P0 是能显著改善大型画布导航和整理的核心能力；P1 是高价值知识管理能力；P2 是范围扩展或产品化能力。

### A. 关系模型与中心化导航

| 优先级 | 功能 | 状态 | 具体差距 |
| --- | --- | --- | --- |
| P0 | 活动节点中心化展示 | 部分具备 | 能一次性居中节点，但没有稳定的 Active Node 状态和邻域重排模式 |
| P0 | 活动节点邻域裁剪 | 缺失 | 不能只显示活动节点的父级、子级、兄弟、跳转，并暂时隐藏远端节点 |
| P0 | 显式创建父级 | 缺失 | 没有从当前节点反向新建一个上级概念的直接命令 |
| P0 | 显式创建子级 | 部分具备 | 可继续追问或拉出下游节点，但没有与生成无关的通用“创建子级概念”动作 |
| P0 | 显式创建跳转关系 | 部分具备 | 引用边接近 jump，但它携带 LLM 上下文语义，不是纯导航关系 |
| P0 | 父级/子级/兄弟/跳转分区 | 缺失 | 当前布局按上下文箭头和对话链排布，没有以活动节点为中心的相对关系区域 |
| P1 | 多父级与跳转的可展开树 | 缺失 | 没有在树中展开同一节点的多个父级、旁路关系和重复引用位置 |
| P1 | 按代展开/折叠子树 | 部分具备 | 节点可折叠自身卡片，但不能按层级展开或隐藏若干代后代 |
| P1 | 组织关系与上下文关系分层 | 缺失 | 目前连线直接决定模型上下文，没有独立的“只组织、不进上下文”关系层 |
| P1 | 自定义关系类型 | 缺失 | 不能定义“支持、反驳、负责、依赖”等关系类型及样式/方向 |
| P1 | 反向链接与未连接提及 | 部分具备 | 可看到流入上下文，但没有统一 backlinks、孤立提及和建议连接列表 |
| P1 | 孤儿节点管理 | 缺失 | 没有集中查看无连接节点、重新挂接或恢复遗忘节点的工作台 |

| --- | --- | --- | --- |

| P0 | Card View | 缺失 | 没有把大量节点按时间或条件分组为可扫读卡片的视图 |

| P1 | Mind Map View | 部分具备 | 当前列树布局接近单向思维图，但不能围绕任意活动节点切换成对称思维导图 |
| P1 | 视图模式切换器 | 缺失 | 没有网络图/树/卡片/大纲之间共享选择状态的统一切换入口 |

| P2 | 演示模式 | 缺失 | 没有隐藏编辑控件、按关系逐步讲解的专用展示模式 |

## 4. 建议优先补齐的最小组合

如果目标是让大型 ThoughtDAG 画布更容易整理，而不是复制一个通用知识库，建议先做下面六项：

1. **活动节点邻域模式**：单击节点后，可切换“全图/局部”，局部只显示一到两层上下游与引用关系。
2. **组织关系层**：新增不进入模型上下文的组织边；父级、子级、跳转属于组织关系，现有实线继续表示上下文流。
3. **标签和自定义类型**：项目级定义，支持多选批量设置。
4. **搜索过滤器**：文本＋节点种类＋标签＋创建时间＋关系范围＋归档状态。
5. **Tree/Card 两个补充视图**：Tree 用于层级导航，Card 用于大量节点整理；选择和定位状态与画布共享。
6. **持久化事务日志**：所有 UI/CLI 修改记录 `before/after`，撤销通过补偿事务完成，刷新后仍可恢复。

这里最重要的架构约束是：**不要把知识组织关系直接等同于 LLM 上下文关系**。ThoughtDAG 的实线箭头具有执行含义；如果照搬“父子关系就是一条普通线”，会破坏“连线即上下文”的核心规则。

## 5. 仍建议补充的截图

现有两张截图已经足够形成第一版清单，不阻塞结论。若要继续写成可实施的 PRD，以下截图最有价值：

1. 搜索结果、过滤器和报告面板，最好包含类型＋标签＋日期组合条件；
2. 一个同时具有多个父级、子级、兄弟和跳转节点的活动节点视图；
3. 同一批数据在 Tree、Card、Outline、Mind Map 四种视图中的样子；
4. “想法属性”“想法类型”“链接类型”面板的展开状态；
5. 多标签页、单节点分享、固定节点和最近访问区域；
6. 时间线、事件、提醒和待办列表。

这些截图主要用于确定交互细节和优先级，不会改变本文对核心差距的判断。
